# 结构模板：单文档项目复盘报告

> 默认形态：**一篇**飞书文档包含所有内容，不拆分。默认读者：分享给其他人看。默认篇幅：精简版与标准版之间。

## 总体结构（四大部分）

```
项目简介（3-6 段 + 1 个定位高亮块）
├── 项目目标与核心定位
├── 关键数字（历时、规模、迭代次数、最终成果）
项目历程（阶段化叙事，5-9 个阶段）
├── 每阶段：做了什么 → 暴露什么问题/转折 → 收获/教训
├── 关键转折点单独强调（如"目标澄清"）
├── 错误 vs 正确版本对比图（有产物对比时）
经验分享（3-5 条，每条 = 具体事件 → 提炼方法 → 可复刻做法）
├── 每条经验从项目真实事件出发，不空谈
├── 教读者"怎么复刻"，而非只记录
最终成果与使用教程
├── 成果能做什么（能力清单）
├── 核心能力证据链（教学原文 → 参数表 → 成品对照，适用于"学习型"项目）
├── 使用教程（输入什么 → 输出什么，分步）
├── 可复用的价值（3-4 点）
```

## 各部分写法

### 1. 项目简介

- 2-3 句话讲清：这是什么项目、核心目标是什么、最终做成什么样。
- 用 1 个高亮块点出**核心定位**（与常见做法不同的地方）。
- 给关键数字：起止时间、迭代次数、最终成果规模（如"15 个函数、4 大类风格、4 次测试通过"）。

### 2. 项目历程（主体，篇幅最大）

- **阶段化叙事**，不是流水账。每个阶段回答：当时目标是什么 → 做了什么 → 暴露什么问题 → 怎么解决/收获什么。
- **迭代/测试融入阶段**：每次测试作为下一个阶段的开头或转折出现，让读者看到"变化与升级"，不要单独开一章"测试对比"。
- **关键转折点**用独立段落 + 加粗强调（例如"需求理解错误 → 目标澄清"是项目分水岭）。
- 有产物对比时，插"错误版本 vs 正确版本"预览图，让读者一眼看懂差异。
- 阶段数 5-9 个为宜；每个阶段 1-3 段。

### 3. 经验分享

- 3-5 条即可，每条一个二级标题，结构固定：**事件/实例（来自本项目）→ 提炼的经验 → 可复刻的做法**。
- 命名用"动词短语 + 冒号 + 结论"，例如"先明确目标：搞清楚文章是教材还是内容源"。
- 这条经验必须是读者能带走的（换一个项目也能用），不是本项目专属。

### 4. 最终成果与使用教程

- **成果能做什么**：能力清单（3-5 条）。
- **核心能力证据链**（对"学方法/学习型"项目必须）：教学原文/来源截图 → 手法/要点参数表 → 配色/关键参数采样 → 成品页对照图 → 一句总结高亮块。让"能力"可验证，而非自说自话。
- **使用教程**：输入什么 → 处理过程 → 输出什么，分 4-6 步，每步一句话说清。
- **可复用的价值**：3-4 点，写"这套做法还能用在别处"。

## 高频返工点（写作时主动避开）

| 返工点 | 避免方法 |
|---|---|
| 太长、太技术化 | 精简版与标准版之间；区分"AI 能自动完成的"和"读者需要掌握的"，只保留后者 |
| 结构割裂（测试/迭代独立成章） | 融入历程叙事，让读者感受升级 |
| 只讲"做了什么"，不讲"怎么复刻" | 经验分享部分给可复刻做法；成果附使用教程 |
| 核心能力只有宣称、没有证据 | 补教学原文 + 参数表 + 成品对照的证据链 |
| 图片失真（近似渲染） | 用真实产物导出（PowerPoint 导出等） |
