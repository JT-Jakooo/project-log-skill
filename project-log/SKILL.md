# Project Log

## Overview

把一次真实协作过的项目（开发、PPT 制作、方案设计、调研等）复盘成一份**单文档、读者视角、证据充分**的报告，默认交付飞书在线文档。核心价值：一次写到位，避免"太长太技术化 / 结构割裂 / 只讲做了什么 / 核心能力无证据"这类高频返工。

素材以飞书文档/会话记录为主要事实来源（用户每版产物均经飞书沉淀），本地文件为补充。

## 工作流

按顺序执行以下 5 步。

### Step 1 · 收集素材（事实来源）

- 以飞书文档、会话记录为主要来源：项目的需求提出、版本演进、用户反馈、交付产物都在其中。
- 本地文件为补充：memory 文件、过程日志、产物目录（PPT/图片/HTML）、时间戳、版本信息。
- 目标：重建时间线 + 关键事件 + 版本演进 + 用户反馈点。回忆不起/检索不到的明确标注「待补充」，**禁止编造**。
- 若关键素材缺失到无法成文（无任何可追溯来源），先向用户询问，不要凭空写。

### Step 2 · 确认方向（开工前一次问清）

只问用户没给的信息，默认值如下，用户明确给了就不问：

- **读者**：默认"分享给其他人看"（不是开发者/当事人自留日志）
- **侧重点**：默认"历程 + 经验教训 + 成果介绍"三者并重
- **篇幅**：默认"精简版与标准版之间"，宁短勿长
- **载体**：**默认飞书在线文档**，用户要求 Word/Markdown 时按用户要求

### Step 3 · 撰写正文（单文档，按结构模板）

按 `references/structure.md` 的单文档结构撰写：**项目简介 → 项目历程 → 经验分享 → 最终成果与使用教程**。全部内容放一篇，不拆分。

- 历程用**阶段化叙事**（每个阶段：做了什么 → 暴露什么问题/转折 → 收获），迭代与测试**融入各阶段**，不并列堆砌。
- 写作全程遵循 `references/writing-principles.md` 的 8 条原则。

### Step 4 · 证据可视化

- 关键成果配图：错误版 vs 正确版对比、教学原文/来源截图、成品预览、参数表。
- 预览图用**真实产物导出**（如 PowerPoint 导出 1920×1080 PNG），不用近似渲染；图要压缩控制体积。
- 图片上传用 `<img path="@./...">` 格式，caption 内双引号改用中文引号「」避免 XML 语法错误。

### Step 5 · 质量门禁自检 + 交付

按 `references/writing-principles.md` 末尾的「交付前自检清单」逐项核对，全部通过后：

1. 创建飞书文档（lark-doc skill 流程），回读验证渲染正确（标题层级、表格、图片、特殊字符）。
2. 交付文档链接，说明结构、字数、图片数。

## Resources

- `references/structure.md` — 单文档结构模板（每部分写什么、写多少、示例写法），撰写正文前必读。
- `references/writing-principles.md` — 8 条写作原则、高频返工点、交付前自检清单，撰写全程对照。
- `references/examples.md` — 两份真实样本中的可复用章节示例（证据链、决策表、卡点表、版本表），需要时参考。
