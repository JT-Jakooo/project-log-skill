# Project Log — 项目复盘 / 全过程日志报告 Skill

一个把已完成项目复盘成**单文档、读者视角、证据充分**的正式报告（默认交付飞书在线文档）的 Doubao Work Skill。

## 这个 Skill 能做什么

- 把一次真实协作过的项目（开发、PPT 制作、方案设计、调研等）复盘成一份结构完整的报告
- 核心价值：一次写到位，避免"太长太技术化 / 结构割裂 / 只讲做了什么 / 核心能力无证据"这类高频返工
- 报告结构固定为四大部分：**项目简介 → 项目历程 → 经验分享 → 最终成果与使用教程**

## 适用场景

当用户要求对某个已完成的项目、工作、任务做总结、复盘、全过程日志、项目回顾、经验教训整理，并期望输出一份可供他人阅读的正式报告时使用。

典型触发语：

- "对这次项目做个复盘"
- "写一份全过程日志"
- "总结一下这个 PPT 制作过程"
- "项目回顾报告"
- "怎么复刻我的工作"

不适合：非复盘性质的普通写作、纯技术文档、无需报告产物的简单问答。

## 工作流（5 步）

1. **收集素材** — 以飞书文档、会话记录为主要事实来源，本地文件为补充；回忆不起的明确标注「待补充」，禁止编造
2. **确认方向** — 开工前只问用户没给的信息（读者 / 侧重点 / 篇幅 / 载体，均有默认值）
3. **撰写正文** — 单文档，按 `references/structure.md` 的结构模板 + `references/writing-principles.md` 的 8 条写作原则
4. **证据可视化** — 关键成果配真实产物导出的对比图、参数表
5. **质量门禁自检 + 交付** — 按自检清单逐项核对后创建飞书文档并回读验证

## 文件结构

```
project-log/
├── SKILL.md                          # 技能主文件（frontmatter + 工作流 + 资源索引）
└── references/
    ├── structure.md                  # 单文档结构模板（每部分写什么、写多少）
    ├── writing-principles.md         # 8 条写作原则 + 常见取舍 + 交付前自检清单
    └── examples.md                   # 可复用章节写法示例（写法要点，非真实项目内容）
```

## 安装方法

把整个 `project-log` 文件夹放到任意一个 Skill 根目录即可：

- 工作区技能目录：`<workspace>\.skills\`
- 用户技能目录：`<workspace>\.user_skills\`

放置后即可通过上述触发语调用。

## 依赖

- 默认交付载体为飞书在线文档（依赖 Doubao Work 的 lark-doc 能力）
- 无其他外部依赖

## 说明

本 Skill 的示例文件仅保留可复用的写法经验，不包含任何真实项目、客户或个人信息，可放心公开使用。
